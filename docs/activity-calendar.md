# Activity Calendar / Timeline — 1.2.0+15

Portfolio → 움직임 기록에서 월간 캘린더와 날짜별 타임라인을 연다. 걸음량은 실제 걸음 수의 네 단계 배경 강도로 표현하고 운동(●), 탐험(◆), 성취(✦)는 별도 표시한다. 빈 날은 중립적으로 남기며 새 점수·streak·실패 표현은 없다. 미래 날짜는 표시만 하고 선택/활동 집계를 막는다.

월 합계는 걸음, GPS 운동 거리/횟수, 새 탐험 지역 수를 따로 보여준다. 이전 달에 해당 지표의 기록이 있을 때만 차이를 표시하며 진행 중인 달과 이전 달 전체 비교임을 명시한다. 날짜별 화면에서 운동 시간/목록과 업적·타이틀·레벨 확인 기록을 볼 수 있고 기존 운동 상세로 이동한다. 몸무게·GPS 내부 값은 노출하지 않는다.

## 날짜와 원본 정책

- `daily_steps.date`는 기존 로컬 dateKey를 그대로 사용한다.
- UTC 시각은 SQLite `localtime`으로 현재 기기 시간대의 날짜로 묶는다. 기존 `startedAt.toLocal()` 정책과 같다. 시간대를 바꾸면 시각 기반 기록의 날짜가 달라질 수 있지만 이미 저장된 걸음 dateKey는 바꾸지 않는다.
- 자정을 넘긴 운동의 거리/시간은 시작일 전체에 귀속한다. 탐험은 기존 `discoveredAt` 날짜에 귀속하므로 종료일과 운동 시작일이 다를 수 있다.
- 업적·타이틀은 XP 원장에 보상이 처음 기록된 날짜다. 과거 운동을 복원/재계산해 늦게 인식한 업적도 원장의 인식일로 표시하며 달성 시점을 추정하지 않는다.
- 레벨은 `character_progress`에서 프로필이 해당 레벨을 확인한 날짜다. 정확한 과거 레벨 상승 시각을 복원할 수 없으므로 “Lv. N 확인”으로 표시한다. 보상함의 업적 행은 중복 표시하지 않는다.
- 마이크로초가 있는 자정 직전/직후 시각은 SQLite의 밀리초 반올림과 UTC 문자열의 가변 길이 소수부에 영향을 받지 않도록 조회한다. 이전 백업의 ISO offset/로컬 성장 시각도 지원한다.
- 미래 날짜/시각은 제외한다. 사용자 기록, XP, 보상 확인 상태는 읽기만 한다.

## 조회/성능/복원

월 화면은 선택 월과 이전 월만 조회한다. 운동은 SQL 일별 COUNT/SUM으로 반환하며 경로/raw GPS/지도/분석을 읽지 않는다. 탐험은 기존 셀 정책에 맞는 이벤트를 검증해 집계한다. Timeline은 성취를 두 개만 미리 보여주고 날짜별 UNION과 keyset cursor로 20일씩 조회하며 ListView.builder와 “이전 기록 더 보기”로 추가 로드한다. OFFSET, 전체 운동 객체 로드, background timer와 새 sensor subscription은 없다.

월/타임라인 조회는 읽기 트랜잭션의 일관된 스냅샷이다. 새 사용자 테이블/캐시/마이그레이션 없이 schema 5 / backup format 3을 유지한다. 삭제 후 날짜 화면·월·타임라인·Portfolio로 돌아올 때 재조회하며 앱 resume에도 월/타임라인을 새로 읽는다. 복원 후 저장된 원본에서 다시 조회하므로 stale cache가 없다. 운동 삭제 후 이미 획득한 업적/탐험은 기존 영구 해금 정책대로 남는다.

20년 분량의 7,300일 걸음·운동·탐험 데이터를 사용하는 호스트 성능 테스트를 제공한다. 전체 raw/저장 경로 테이블이 없어도 월/타임라인 조회가 작동한다. 이는 실제 기기 지연/배터리 측정의 대체가 아니다.

## 접근성/공유

기존 design token과 Light/Dark를 사용한다. 날짜 칸에는 숫자/indicator만 표시하고 큰 글꼴의 상세 텍스트는 날짜 화면에서 제공한다. 달력 숫자는 16sp 고정이며 날짜/걸음/활동과 선택 동작은 semantics로 제공한다. 최소 48dp 날짜 터치 폭을 위해 좁은 화면의 달력은 안내와 함께 가로 스크롤한다. 나머지 내용은 시스템 글꼴 크기를 따른다.

월간 카드 PNG는 720×900(4:5). 월/총 걸음/운동 거리·횟수/지역 수/대표 업적 또는 타이틀 하나만 허용한다. 위치·route·체중·내부 ID·날짜별 위치는 포함하지 않는다. 기존 preview/시스템 공유/MediaStore 갤러리 저장 흐름을 재사용하며 자동 전송은 없다.
