# v1.2.0 (15) 지역 탐험

## 영역과 판정

- 표준 Web Mercator z17 셀, deterministic ID `wm17.<x>.<y>.v1`, `explorationRuleVersion = 1`. 적도 약 306m, 서울 약 244m로 위도에 따라 달라지며 극지방(±85° 밖)은 제외합니다. 주소나 새로운 정밀 좌표를 탐험 테이블에 저장하지 않습니다. 셀 ID도 대략적인 위치를 나타내므로 백업은 비공개로 보관해야 합니다.
- 기존 `MovementAnalyzer`의 `moving && recordEligible` 구간만 후보로 사용합니다. 기존 분석 정책/버전, 운동 합계, 100m/500m/1km 결과와 raw GPS는 변경하지 않습니다.
- 원본 점은 accepted/stationary_noise, 정확도 ≤15m, 운동 종류별 이동/최고 속도 범위를 만족해야 합니다. 정확도 반경+5m가 셀 경계 안에 들어오는 점만 확인합니다.
- 같은 셀·segment의 연속 점 3개 이상, 20초 이상, 누적 이동 ≥60m, 첫 점 대비 순변위 ≥50m에서 해금합니다. 각 이동량은 좌표 거리와 두 점의 낮은 센서 속도×시간 중 작은 값입니다. 단일 점, 경계 오차, 정지 흔들림, 15초 초과 단절, 일시정지를 이어 붙이지 않습니다. 셀 사이를 보간하지 않습니다.
- 보수적인 기준이므로 모퉁이 통과, 짧은 방문, 정확도가 낮은 도심 GPS는 실제 방문이어도 해금되지 않을 수 있습니다. 차량 이동 등 모든 오탐을 GPS만으로 완전히 배제할 수는 없습니다. 실제 판정 품질은 S26 야외 검증이 필요합니다.

## 동작과 화면

운동 저장/기록 서비스 종료 뒤 isolate에서 계산하고 발견 개수를 운동 상세에 표시합니다. 탐험 계산 실패가 저장된 운동을 취소하지 않으며 지도에서 재시도할 수 있습니다. 운동 상세의 탐험 지도에서 이번 운동의 새 영역을 보라색, 기존 방문 영역을 초록색으로 구분합니다.

Portfolio → All-time Map에서 누적 영역 수, 이번 달 발견 수와 방문 overlay를 확인합니다. `지난 운동의 탐험 추가`는 명시적 확인 후 raw GPS가 있는 완료 운동만 오래된 순으로 처리합니다. 진행 중 운동이 있으면 차단합니다. 원본 없는 기록은 추정하지 않습니다. 발견일은 최초 처리한 운동의 종료일(로컬 달력 기준)이며 기존 발견일은 소급 변경하지 않습니다. 재시도/재계산은 중복 해금하지 않습니다.

완료 운동을 삭제해도 이미 해금한 영역과 성장 보상은 유지하며 삭제 확인창에서 안내합니다. 운동/경로/raw GPS는 기존 삭제 정책대로 삭제합니다. 탐험을 포함한 전체 데이터 교체는 format 2 백업 복원으로 처리합니다.

## 성장과 공유

- 새 셀마다 10 XP, entitlement key `exploration.cell:<cellId>:v1`.
- 일일 새 셀 3곳 퀘스트 30 XP. 날짜별 ledger key로 지급하고 날짜가 바뀌면 오늘 진행만 초기화합니다.
- 1/10/50/100개 탐험 업적은 각각 30/80/150/250 XP와 타이틀을 해금합니다. 기존 XP/레벨 규칙과 업적 ID는 유지합니다.
- 셀, 퀘스트, 업적 보상은 기존 UNIQUE reward ledger/transaction을 재사용합니다. 재계산, 동시 갱신, 운동 삭제/재추가로 XP를 다시 주지 않습니다. 과거 운동 추가는 해당 종료일의 퀘스트 보상을 한 번 지급할 수 있습니다.
- 탐험 카드는 720×720 PNG로 이번 운동/이번 달 발견 수와 총 영역 수만 표시합니다. Light/Dark preview → 시스템 공유/갤러리 저장을 재사용하며 지도·셀 ID·정밀 위치·시각은 카드에 포함하지 않습니다. 기존 운동 공유의 200m 시작/끝 숨김도 변경하지 않습니다.

## 저장과 호환

기존 schema 4의 `exploration_events`(eventKey, regionId, sourceSessionId, modelVersion, discoveredAt)를 그대로 사용하므로 사용자 테이블 migration/버전 변경은 필요 없습니다. 기존 schema 1→4 migration도 유지합니다. format 2/schema 4 백업은 이미 이 테이블을 포함합니다. format 1/schema 3을 읽을 때 기존 성장/탐험 데이터는 유지합니다.

새 `exploration_scans`는 session.updatedAt/분석 정책/탐험 규칙 버전을 키로 하는 재계산 방지 캐시입니다. 필요할 때 생성하며 사용자 데이터가 아니므로 백업에 포함하지 않고 복원 시 transaction 안에서 비웁니다. 삭제된 세션의 스캔 캐시는 FK cascade로 제거합니다. 알 수 없는 버전/비정상 ID/미래 날짜의 이벤트는 현재 탐험 수와 보상에서 제외합니다.

구버전 백업 복원 시 유지되는 탐험의 sourceSessionId는 해제합니다. 전체 백업에도 삭제된 원본 운동의 ID가 남아 있다면 복원 시 해당 연결만 해제합니다. 셀/발견 시각/XP는 보존하며 새 기기에서 운동 ID가 재사용돼 다른 운동의 새 발견으로 표시되는 것을 방지합니다. 정상 원본 운동이 함께 있는 format 2 백업은 연결까지 그대로 복원합니다.

## 성능과 검증

운동 중 탐험 타이머·GPS 요청·polygon 계산을 추가하지 않습니다. bestForNavigation/약 2초 수집, raw 저장, UI 가시성 timer와 기존 checkpoint transaction 정책은 유지합니다. 별도 dependency도 추가하지 않습니다.

지도는 7개 확대 수준의 셀 인덱스를 한 번 구성하고 가시 영역 bucket만 조회합니다. 화면당 최대 512개 bucket까지 단순화하며 날짜 변경선/경도 wrap도 처리합니다. 확대하면 정확한 z17 셀 polygon을 표시하고 축소하면 묶인 위치를 작은 점으로 표시합니다. 축소 bucket 전체를 방문한 면적으로 칠하지 않습니다. polygon은 최대 1,024개를 캐시합니다. 합성 24,001 GPS 점 + 10,000 셀 + 1,000회 가시 영역 조회 테스트는 최종 로컬 전체 테스트에서 826ms였습니다. 이는 센서/실사용 배터리 측정이 아닙니다.

`dart format .`, `flutter analyze`, Flutter 테스트 220개(비공개 S26 입력 4개 포함), native `:app:stepPolicyChecks` 9개가 통과했습니다. CI에는 비공개 입력이 없으므로 216개 실행/4개 skip이 예상됩니다. 정식 서명 release APK를 빌드하며 산출물/키/개인 입력은 Git에 포함하지 않습니다.

S26 미연결 상태에서 Diligent_API36(Android 16/API 36)에 기존 서명과 같은 정식 APK를 업데이트 설치했습니다. 합성 운동 3개에서 63개 셀 발견, 반복 추가 0개, 상세 운동의 새 셀 21개 표시, 탐험 퀘스트 완료, 1/10/50개 업적 해금, 타이틀 장착/복원, 앱 재시작 후 Lv.7/2,035 XP 보존을 확인했습니다. Light/Dark, 320dp·글꼴 2.0 지도/카드, 시스템 공유창과 갤러리 저장도 확인했으며 화면 캡처는 Git에서 제외한 로컬 검증 폴더에 보관합니다.

탐험 포함 백업을 앱에서 내보내고 전체 복원했습니다. 설치 전 일일 기록 1개·운동 3개·경로/raw GPS 각 2,703개·걸음 7일·기존 타이틀의 모든 행/열과 기존 보상 19개가 보존됐습니다. 복원 DB와 백업 8개 테이블이 전 항목 일치하고 schema 4/탐험 63개는 유지되며 스캔 캐시는 비워졌습니다. 이 수치는 합성 데이터 검증이며 실제 보행 정확도가 아닙니다.

자체 리뷰에서 비정상 셀 ID 정수 파싱, 날짜 변경선/지도 조회량, 축소 overlay의 방문 면적 과장, 삭제 후 탐험 유지 안내, 복원 후 스캔 캐시와 운동 ID 재사용 시 오연결을 확인·보완했습니다. GPS/FGS/native 만보기 코드는 변경하지 않았습니다. 실제 GPS 이동/해금 품질, 걸음 정확도, 장시간 화면 OFF 센서/health FGS, 배터리, TalkBack 음성 탐색은 S26 검증 항목으로 남깁니다.
