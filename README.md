# Diligent Life · 1.2.0 (15)

운동·몸무게의 변화를 기기에 보관하는 개인 라이프 트래커입니다. 광고, 계정, 앱 서버가 없습니다. Android 1.0.0(12) 정식 서명 APK/AAB 빌드와 S26(SM-S942N)의 앱 설치·기존 데이터 복원 검증을 완료했습니다. 해당 1.0.0 검증은 DB schema 3과 backup format 1 기준입니다.

이전 버전 1.0.1(13)은 GPS 수집·분석 정책을 유지하면서 표시 타이머·지도 캐시·중복 체크포인트를 최적화합니다. 전체 149개 테스트(개인 입력 3개 포함), 실제 S26 16개 세션의 릴리즈 HEAD 대비 분석 회귀, 정적 분석과 정식 서명 APK 빌드·서명 검증이 통과했습니다. S26에 정식 서명 업데이트 설치와 운동·raw GPS·몸무게 데이터 전 항목 보존을 확인했습니다. 실제 배터리 절감률 측정은 남아 있습니다. 구현·검증 범위는 [배터리 최적화 1차 기록](docs/battery-v1.0.1.md)에 있습니다.

## 1.2.0 지역 탐험

활동 알림에서 오늘 걸음·목표와 운동 거리·시간·평균 페이스를 확인하고 운동을 일시정지/재개할 수 있습니다. 알림 갱신은 합쳐서 처리하며 기존 센서·GPS·저장 정책은 유지합니다. [알림 UX와 검증 범위](docs/activity-notifications.md).

Today의 Lv/Title에서 프로필로 들어가 로컬 아바타, 외형 해금·장착, 보상함과 타이틀을 확인합니다. 위치·체중 없는 프로필 공유 카드를 제공합니다. 현재 저장 형식은 schema 5 / backup format 3이며 이전 format 1·2도 읽습니다. [Character/Profile 기록](docs/character-profile.md)을 참고하세요.

운동 종료 후 정확도가 좋은 연속 이동에서 새 영역을 발견합니다. 서울 기준 약 244m의 지도 셀 안에서 충분히 이동해야 해금되며 단일 GPS 점·정지 흔들림·나쁜 정확도로는 해금하지 않습니다. Portfolio의 All-time Map에서 누적/이번 달 탐험과 이번 운동의 새 영역을 확인하고, 위치 없이 발견 개수만 담은 카드를 공유하거나 갤러리에 저장할 수 있습니다. 새 영역 XP·일일 퀘스트·업적·타이틀은 중복 지급하지 않습니다.

지역 탐험 최초 구현은 schema 4와 backup format 2를 유지했습니다. 과거 운동은 지도에서 사용자가 선택해 추가하며 raw GPS가 없는 기록은 추정하지 않습니다. GPS 수집·분석·만보기 정책은 바꾸지 않습니다. 해금 기준·성능·검증 제한은 [지역 탐험 기록](docs/exploration-v1.2.md)을 참고하세요.

## 1.1.0 UX와 나의 성장

일상 만보기, 오늘 걸음/목표·최근 7일·주/월 통계, Lv/XP·퀘스트·업적·타이틀, 운동 상세 scrubber, 성취 이미지·갤러리 저장, 로컬 테마 선택을 추가했습니다. 기존 GPS/분석/배터리 최적화는 유지합니다. DB schema 4와 backup format 2로 새 데이터를 보존하며 기존 백업도 읽습니다. S26 정식 서명 업데이트·기존 전체 데이터 보존·실제 걸음 증가·화면 OFF/GPS 동시 기록·재부팅 복원·테마·scrubber·시스템 공유·갤러리 저장을 확인했습니다. 실제 보행 수 대비 정확도, 자정 경계, 장시간 배터리 비교는 남아 있습니다. 세부 규칙과 검증 범위는 [1.1.0 UX 기록](docs/ux-v1.1.0.md)을 참고하세요.

v1.1 UI polish는 오늘 걸음 중심의 hierarchy, 성장 progress, 운동 상세 탐색과 접근성 있는 Theme 선택을 정리합니다. 디자인 토큰과 검증 범위는 [UI polish 기록](docs/ui-polish-v1.1.md)을 참고하세요.

main baseline의 리뷰·검증 범위와 남은 S26 실사용 검증은 [v1.1 baseline 기록](docs/baseline-v1.1.md)을 참고하세요. 이후 신규 개발은 최신 main에서 별도 작업 브랜치를 생성하고 PR 리뷰·CI 통과 후 Squash Merge합니다.

Portfolio의 **움직임 기록**에서 월간 캘린더·날짜별 운동과 성장 기록·날짜 단위 Timeline을 돌아보고, 위치 없는 월간 요약 카드를 공유/저장할 수 있습니다. 원본 조회만 사용하며 schema 5 / backup format 3과 GPS·만보기·XP 규칙은 유지합니다. 날짜/성능/검증 범위는 [Activity Calendar 기록](docs/activity-calendar.md)을 참고하세요.

## 데이터와 계산 정책

현재 SQLite schema 5를 사용하며 기존 schema 1·2·3·4에서 업그레이드를 지원합니다. schema 5는 외형·장착·보상 확인 테이블 하나만 추가합니다. 분석 재계산은 파생 캐시만 갱신하며 기존 운동 합계와 raw GPS를 수정하지 않습니다. raw GPS가 없는 과거 운동은 저장 경로로 제한적으로 분석합니다.

기록 당시 거리와 후처리 분석 거리는 서로 다른 기준이며 화면에서 구분합니다. 운동시간은 수동 일시정지를 제외한 기록 시간입니다. 이동·정지·미분류 시간은 GPS 분석 결과로, 신호가 부족한 시간을 이동으로 가정하지 않습니다. 칼로리는 기록 시간과 당시 체중의 MET 추정치이며 실제 소비량 측정이 아닙니다. 개인 기록에는 신뢰도와 최소 개선 임계값을 적용합니다. 상세 정책은 [v0.9 분석 정책](docs/analysis-v0.9.0.md)을 참고하세요.

원본에는 정확한 위치·시각·체중이 포함됩니다. 일반 기록은 앱의 로컬 저장소에 있으며 분석용 서버로 전송하지 않습니다. 지도는 OpenStreetMap 타일을 인터넷으로 요청하므로 타일 서버에 IP와 요청 영역이 전달됩니다. 이미지 공유는 미리보기 후 사용자가 시스템 공유창에서 선택합니다. 운동 공유의 시작·끝 위치 200m 숨김은 기본 켜짐이며 완전한 익명화를 보장하지 않습니다.

Android OS 자동 백업·기기 이전은 비활성화되어 있습니다. 앱 삭제·기기 분실 시 수동 백업이 없으면 복구할 수 없습니다. 앱 재시작은 마지막 커밋된 체크포인트의 진행 중 운동을 일시정지로 복원합니다. 비정상 종료 직전 미저장 데이터는 복구하지 못하며 종료된 동안의 시간·거리를 만들어 넣지 않습니다.

## 백업과 복원

1. 설정 → **기록 백업과 복원** → 내보내기에서 `.diligent` 파일을 안전한 개인 폴더에 저장합니다.
2. 복원 전에 현재 기록도 별도 파일로 내보냅니다.
3. 가져오기에서 파일을 선택하고 검증된 기록 수를 확인한 다음 전체 교체를 승인합니다. 병합하지 않습니다.

현재 백업 format 3 / schema 5는 일일 기록, 운동 세션, 저장 경로, raw GPS와 걸음·XP 원장·타이틀·탐험·외형·장착·보상 확인 데이터를 보존합니다. 내보내기 전에 만보기의 대기 데이터를 저장하며 저장 실패 시 내보내기를 중단합니다. 기기별 sensor cursor·파생 캐시·지도 타일·알림 설정은 제외합니다. 기존 format 1 / schema 3과 format 2 / schema 4도 읽습니다. format 1은 현재 걸음·XP·타이틀·탐험을 유지합니다. 프로필 데이터가 없는 format 1·2는 장착·보상 확인 상태를 초기화하고 활동 기준으로 외형을 다시 해금합니다. 임시 DB에서 형식·관계·범위·완료 행·행 수를 검증하며 손상·미지원 파일은 원본을 바꾸지 않고 거부합니다. 교체 실패는 트랜잭션으로 롤백합니다. 진행 중 운동·미저장 입력이 있으면 복원을 차단하고, 백업의 미완료 운동은 일시정지로 복구합니다. 백업은 암호화되지 않으며 위치 숨김도 적용되지 않습니다.

## 개발·검증

Flutter 3.47.2 / Dart 3.13.2, JDK 17, Android SDK가 필요합니다. applicationId는 `com.v4n1lla.diligent_life`이며 앱 이름은 Diligent Life입니다. 버전 원본은 `pubspec.yaml`, 화면 표시는 `lib/app_info.dart`이며 테스트로 일치를 확인합니다.

```sh
flutter pub get
dart format .
flutter analyze
flutter test
flutter build apk --release
flutter build appbundle --release
```

기존 로컬 검증에서 `flutter analyze`와 기본 테스트 140개가 통과했습니다. 개인정보 기반 후속 테스트 2개도 입력을 제공한 별도 실행에서 통과했습니다. S26 복원 전후 일일 기록 2개·운동 11개·경로 3,366개·raw GPS 8,458개의 모든 원본 행과 열이 일치했습니다.

GitHub Actions는 format 검사, analyze, test, release APK/AAB 컴파일을 수행합니다. 개인 세션은 저장소·CI에 포함하지 않아 개인정보 기반 테스트 4개는 CI에서 명시적으로 skip합니다. 로컬 후속 검증에는 `LEGACY_BACKUP_DATA`(기존 백업), `S26_REGRESSION_DATA`(기존 분석 회귀 입력), `S26_BATTERY_DATA`와 `S26_BATTERY_BASELINE`(최신 전체 세션과 릴리즈 HEAD 분석 기준값)을 제공합니다. 1.1.0 기존 데이터 보존 회귀에는 `S26_V110_BACKUP`(private NDJSON 백업)을 추가로 제공합니다. synthetic 12,005/24,001 표본과 다중 세션 성능 테스트는 CI에도 유지합니다. 1.0.0 릴리즈의 원격 CI 이력은 [최종 릴리즈 검증 기록](docs/release-v1-final.md#remote-github-actions)을 참고하세요.

## 서명과 알려진 제한

- 정식 서명키로 Android 1.0.0(12) APK/AAB 빌드와 서명 검증을 완료했습니다. release 빌드는 서명 설정이 없거나 불완전하면 실패합니다. CI는 일회용 검증키를 사용하므로 CI 산출물은 정식 배포용이 아닙니다. 상세 설정은 [Android 릴리즈 서명](docs/android-release-signing.md)을 참고하세요.
- 정식 서명은 Git에서 제외한 `android/key.properties`에 `storeFile`(절대 경로 권장), `storePassword`, `keyAlias`, `keyPassword`를 설정합니다. 키·비밀번호·APK/AAB는 저장소에 커밋하지 않습니다. 다른 서명의 기존 설치에는 덮어쓸 수 없으므로 삭제 전 반드시 백업해야 합니다.
- GPS 정확도, 제조사 절전, 실내·화면 OFF 환경에 따라 누락·오차가 생깁니다. GPS가 없는 구간은 보간해 기록을 만들지 않습니다. 지도는 인터넷이 필요하며 실패 시 다시 시도할 수 있습니다.
- 앞으로 실기기 테스트는 S26(SM-S942N)만 사용합니다. S20(SM-G988N)은 더 이상 테스트에 사용하지 않으며 문서의 S20 결과는 과거 검증 이력입니다.
- 자동 semantics·터치 영역 검사와 실제 TalkBack 음성 탐색은 구분합니다. 장시간 야외·백그라운드 운동과 실제 보조기술 사용자 검증은 별도 확인이 필요합니다.
- iOS는 macOS/Xcode 빌드, 실기기 권한·백업 정책 검증 전 출시 대상에서 제외합니다.

변경 이력은 [CHANGELOG](CHANGELOG.md), 과거 구현·검증 기록은 [개발 이력](docs/development-history.md)에 있습니다.
